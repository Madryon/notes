Network Topologies

🧠 Remember all 6 — "Big Stars Real Make Tree Hybrid": Bus · Star · Ring · Mesh · Tree · Hybrid
🚌 Bus

All devices on single backbone cable. Terminators at both ends.

✓ Cheap, simple setup
✗ Single point failure
⭐ Star

All devices connect to central hub/switch. Most common today.

✓ Fault isolation
✗ Hub failure = network down
💍 Ring

Devices form closed loop. Token passing used. Each node = repeater.

✓ No collision
✗ One failure breaks ring
🕸️ Mesh

Every device connected to every other. Full mesh = n(n-1)/2 links.

✓ Most reliable
✗ Expensive, complex
🌳 Tree

Hierarchical — Bus + Star combo. Root node at top.

✓ Scalable
✗ Root failure = all down
🔀 Hybrid

Mix of 2+ topologies (e.g. Star+Bus). Real networks use this.

✓ Flexible
✗ Complex & costly
Mesh Formula: Full mesh links = n(n-1)/2 · Ports per device = n-1 · Example: 5 nodes → 5×4/2 = 10 links

Signals & Maximum Data Rate

Analog Signal
Continuous (sine wave)
  • Infinite values, smooth curve
  • Parameters: Amplitude, Frequency, Phase
  • Example: Sound, old telephone
Digital Signal
Discrete (square wave)
  • Only 0 or 1, stepping pattern
  • Parameters: Bit rate, Bit interval
  • Example: Computers, CDs
🧠 Analog vs Digital: Dimmer switch (analog — infinite) vs Light switch (digital — ON/OFF only)

Nyquist & Shannon Theorems

🧠 "Nyquist = Noiseless, Shannon = Signal noise"

Nyquist (Noiseless Channel)

Max Rate = 2 × B × log2(M)

B = Bandwidth (Hz), M = number of signal levels
Example: B=3000Hz, M=8 → 2×3000×3 = 18,000 bps

Shannon (Noisy Channel)

Max Rate = B × log2(1 + SNR)

SNR = Signal/Noise ratio (linear scale)
SNR(dB) = 10×log10(SNR)
Practical rate = min(Nyquist, Shannon)

⚠️ Bit Rate = Baud Rate × log2(M). Bit rate ≠ Baud rate when each symbol carries multiple bits.

Error Detection & Correction Techniques

🧠 "Pigs Can't Hamster": Parity · CRC · Checksum · Hamming Code
MethodHow it worksDetectsCorrectsUsed in
Parity CheckAdds 1 bit so total 1s = even (or odd). 2D parity for correction.Single-bit errorsNo (2D: yes)RAM, simple systems
ChecksumDivide into segments, sum all, 1's complement = checksum. Receiver: sum+checksum=all 1s.Most errorsNoTCP, UDP, IP headers
CRCXOR polynomial division. Sender appends r-bit remainder. Receiver divides; remainder=0 → no error.Burst errors (up to r bits)NoEthernet, Wi-Fi, USB, ZIP
Hamming CodeParity bits at positions 2^0,2^1,2^2... Syndrome = error bit position.2-bit errors1-bit errorsECC RAM, memory

CRC check bits = r (degree of generator polynomial)
🧠 Hamming trick: Parity bits go at positions 1, 2, 4, 8, 16... (powers of 2). Error position = sum of failed parity positions (syndrome).

ARQ Error Recovery Protocols

🧠 "Stop Going Selectively" (efficiency increases): Stop-and-Wait · Go-Back-N · Selective Repeat
FeatureStop-and-WaitGo-Back-N (GBN)Selective Repeat (SR)
Sender window12n − 12n-1
Receiver window11 (always!)2n-1
On error: retransmit1 frameError + all afterError frame only
Rx bufferingNoNoYes (out-of-order)
EfficiencyLowest — 1/(1+2a)Medium — W/(1+2a)Highest
ComplexitySimpleMediumMost complex
Stop-and-Wait: η = 1/(1+2a)   where a = Tp/Tf
GBN: η = W/(1+2a) if W < 1+2a, else η = 1
🧠 Window trick: GBN sender = 2n−1 (one less) · SR both = 2n-1 (half) · GBN receiver = ALWAYS 1

TCP Flags: URG · ACK · PSH · RST · SYN · FIN — "Until Amazing People Remember Sending Forms"

3-Way Handshake (Connection Setup)

Client→SYN (seq=x)→Server
Client←SYN+ACK (seq=y, ack=x+1)←Server
Client→ACK (ack=y+1)→Server

4-way termination: FIN→ACK→FIN→ACK (each direction closes independently)

Flow & Congestion Control

  • Flow control: Receiver advertises rwnd (receive window). Prevents buffer overflow.
  • Congestion control: Sender maintains cwnd (congestion window). Network-level.
  • Actual send = min(rwnd, cwnd)
  • Slow Start: cwnd doubles each RTT (exponential) until ssthresh
  • Cong. Avoidance: cwnd increases by 1 MSS per RTT (linear)
  • 3 dup ACKs: ssthresh=cwnd/2, fast retransmit

FTP, SMTP, Telnet, HTTP & URL

FTP — File Transfer Protocol (RFC 959)
  • Port 21: Control connection (persistent) — commands
  • Port 20: Data connection (opens per file) — file data
  • Uses TCP. Two separate connections.
  • Active mode: Server connects to client (port 20)
  • Passive mode: Client connects to server (random port) — firewall-friendly
  • Sends credentials in plaintext — not secure!
  • FTPS = FTP + SSL · SFTP = SSH-based · TFTP = UDP, no auth
🧠 "21 Controls, 20 Delivers"
SMTP — Simple Mail Transfer Protocol
  • Port 25 (server-to-server), Port 587 (client-to-server)
  • Used only for SENDING emails. Uses TCP.
  • Push protocol — sender pushes to mail server
  • Commands: HELO, MAIL FROM, RCPT TO, DATA, QUIT
  • Response codes: 220=Ready, 250=OK, 550=User unknown
  • MIME: extends SMTP for binary/multimedia attachments
Email flow: Client →SMTP→ Sender Server →SMTP→ Receiver Server →POP3/IMAP→ Receiver
🧠 "SMTP = Send Mail To People" · POP3=110 (download) · IMAP=143 (access)
Telnet — Remote Login Protocol
  • Port 23. Uses TCP. Application layer.
  • Allows remote terminal access to another machine
  • Uses NVT (Network Virtual Terminal) for character encoding
  • Option negotiation: WILL / WONT / DO / DONT
  • Insecure: transmits everything (inc. passwords) as plaintext
  • Replaced by SSH (port 22) for secure remote access
🧠 Telnet = "Type Everywhere, Login Network" — plain text = insecure
HTTP — HyperText Transfer Protocol
  • Port 80 (HTTP) / Port 443 (HTTPS). Uses TCP.
  • Stateless — each request is independent
  • Methods: GET (retrieve) · POST (send data) · PUT (update) · DELETE · HEAD
  • Response codes: 2xx=OK · 3xx=Redirect · 4xx=Client error · 5xx=Server error
  • HTTP/1.0 = non-persistent · HTTP/1.1 = persistent (default) · HTTP/2 = multiplexed
  • Cookies/sessions used to add state on top of HTTP
🧠 HTTP codes: "I Successfully Redirected, Client got Server error" → 1·2·3·4·5xx

URL — Uniform Resource Locator

DNS — Domain Name System (Port 53)

🧠 DNS = "Domain Name to IP System" — phonebook of the internet. UDP for queries, TCP for zone transfers.

DNS Resolution Steps:

1. Browser checks local cache
2. Query to Local Resolver (ISP)
3. Resolver queries Root Name Server
4. Root returns TLD Name Server address
5. TLD returns Authoritative Server address
6. Authoritative returns final IP address
7. Resolver caches & returns IP to browser
🧠 "Brave Rascals Run To Answer": Browser cache → Resolver → Root → TLD → Authoritative

⚠️ Top Exam Traps — Must Read Before Exam

1. TCP header min = 20 bytes · UDP header = exactly 8 bytes (fixed, always)
2. GBN receiver window is ALWAYS 1. SR receiver window = 2n-1. Getting these swapped = guaranteed mark loss.
3. CSMA/CD = wired Ethernet (collision detected DURING transmission). CSMA/CA = wireless Wi-Fi (collision AVOIDED before).
4. SMTP = SENDING email only. POP3/IMAP = receiving/accessing email. Very commonly confused.
5. DNS uses UDP port 53 for queries but TCP port 53 for zone transfers. NOT purely UDP.
6. Ethernet minimum frame = 64 bytes. If data < 46 bytes → PADDING is added to reach minimum.
7. FTP uses TWO TCP connections: port 21 (control, persistent) and port 20 (data, opens per file).
8. Telnet = insecure (plain text, port 23). SSH = secure (encrypted, port 22). Always distinguish these.
9. DHCP is successor to BOOTP. Both use UDP ports 67/68. DHCP added dynamic IP + lease concept.
10. WWW ≠ Internet. Internet = physical infrastructure. WWW = one service/application running ON the internet.
11. WDM is ONLY for fiber optic cables — NEVER copper. DWDM = Dense WDM (closer wavelength spacing).
12. Walkie-talkie = Half Duplex (NOT simplex). Mobile phone call = Full Duplex.
